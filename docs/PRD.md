# 마이링크 (MyLink) 기획 및 기능 정의서 (PRD)

## 1. 프로젝트 개요
- **프로젝트명:** 마이링크 (MyLink)
- **목적:** 여러 플랫폼에 흩어져 있는 사용자의 링크를 단 하나의 통합된 페이지로 모아서 공유할 수 있는 '멀티 링크 프로필' 서비스 구축
- **대상 사용자:** 개발자 (Developer)

## 2. 핵심 기능 목록 (필수 구현)
본 서비스는 복잡한 부가 기능(테마, 이미지 업로드, 정렬 등)을 배제하고 개발자 대상의 필수 기능에만 집중하여 MVP를 구현합니다.

| 기능 그룹 | 기능명 | 상세 설명 |
| -------- | ------ | --------- |
| **인증** | 구글 소셜 로그인 | **Firebase Auth**를 활용한 구글 소셜 계정 단일 가입 및 로그인 |
| **프로필** | 식별자(Slug) 자동 설정 | 가입 시 사용자의 구글 지메일(Gmail) 주소 아이디(이메일 앞부분)를 추출하여 URL 슬러그(`displayName`)로 자동 설정 |
| **프로필** | 프로필 관리 (인라인 편집) | 실제 화면 표시 이름(`username`) 및 한 줄 소개글 설정<br/>• **수정 방식:** 수정 화면 분리 없이 표시 이름과 소개글을 **인라인 편집(Inline Editing)** 적용<br/>• **제외 기능:** 프로필 이미지 업로드 기능 없음 |
| **링크** | 링크 관리 (인라인 편집) | 웹 링크(타이틀 + URL)의 추가, 수정, 삭제 기능 제공<br/>• **수정 방식:** 타이틀과 URL 모두 별도 모달 없이 화면상에서 **인라인 편집(Inline Editing)** 적용<br/>• **제외 기능:** 드래그 앤 드롭 순서 변경 없음, 활성화(on/off) 기능 없음 |
| **링크** | 파비콘 자동 연동 | 사용자가 링크 등록 시 **Google Favicon API**를 호출하여 해당 URL의 파비콘을 추출해 링크 아이콘으로 자동 표시 |
| **퍼블릭** | 방문자용 프로필 페이지 | `도메인/displayName` 형태의 방문자 접속용 웹페이지 렌더링<br/>• **시스템 예약어 사용 불가:** 시스템 페이지(예: login, admin 등)와의 라우팅 충돌을 방지하는 유효성 체크 필수 |

*(※ 이미지 업로드, 테마 디자인 설정, 모바일 뷰 미리보기 창 등은 요구사항에서 완전히 제외합니다.)*

## 3. 기술 및 데이터베이스 정책
### 3.1. 기술 스택 핵심 요소
- **인증 및 백엔드:** Firebase (Auth, Firestore)
- **외부 API 연동:** Google Favicon API (링크 생성 시 파비콘 이미지 주소 획득)

### 3.2. 데이터베이스 모델링 구조 (Firebase Firestore)
- **사용자 문서 (User Document):** 유저 정보 문서 내에 URL 라우팅용 슬러그(`displayName`)와 화면 표시용 실제 이름(`username`)을 명확히 구분하여 저장합니다.
  - `displayName`: URL 접속 경로를 결정하는 식별어 (슬러그). 계정 인증 시 구글 이메일의 `@` 앞부분을 추출하여 값으로 고정 설정 (`도메인/displayName` 라우팅)
  - `username`: 프로필 화면에 크게 노출되는 사용자의 실제 표시 이름 (인라인 편집으로 언제든 수정 가능)
- **서브 컬렉션 (Sub-collection):** 사용자가 등록하는 여러 개의 개별 링크 리스트 데이터는 사용자 문서(User Document) 하위에 서브 컬렉션(Sub-collection)으로 집어넣어 효율적으로 분리 관리합니다.

## 4. 추후 추가 예정 기능
- **단일 링크 클릭 수 조회:** 개별 링크들이 각각 몇 번 클릭되었는지 측정하는 카운트 기능을 향후에 추가합니다. (전체 페이지 통계 기능은 없음)
